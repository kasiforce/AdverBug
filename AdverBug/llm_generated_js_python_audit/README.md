# JavaScript and Python LLM-generation provenance audit

Audit date: 2026-10-29 (Asia/Shanghai).

## Scope and method

The audit covered all 95 repositories in
`github_repos_javascript_fresh_projects_sorted.csv` and all 122 repositories in
`github_repos_python_sorted.csv`. The README on the recorded default branch was
successfully fetched for all 217 repositories.

README text was searched for explicit code-provenance statements such as
“entirely written by Claude”, “AI-generated code”, “LLM-generated project”,
“no human-written code”, and “vibe-coded”. Every automatic match was then
manually classified to reject false positives. Mentions of AI products,
LLM-generated *runtime input*, or projects that merely integrate an LLM do not
establish that the repository's source code was generated by an LLM.

## Result

No repository in either CSV has README evidence as strong as ResForge's
statement that all code, tests, and documentation were generated by named
models.

The JavaScript list contains one ambiguous candidate:

- `career-ops-hq/career-ops` displays a **Built with Claude Code** badge.
  However, the same README identifies a human creator and 700+ contributors,
  and does not state that all or most source code was generated by Claude.
  It is therefore classified as **AI-assisted**, not as a verified fully
  LLM-generated repository.

No Python repository contains a sufficiently explicit code-generation
provenance statement. Many entries are LLM frameworks or AI applications—for
example inference engines, agent frameworks, and model-training projects—but
their subject matter is not evidence about who or what wrote their source code.

## Conditional complexity result for career-ops

For completeness, the ambiguous JavaScript candidate was cloned at
`91a1fd669b55d20be62349487219792a68828a19` and analyzed with the benchmark's
inclusive conjunction:

```text
LOC >= 100 AND cyclomatic complexity >= 10 AND syntactic call out-degree >= 5
```

The extractor found 539 production JavaScript files, 2,361 functions, and 8
functions satisfying all three conditions. These counts describe the audited
HEAD, not the older `metric_sha` stored in the source CSV. Passing the complexity
filter does not strengthen the repository's LLM-generation provenance.

## Recommended paper wording

For the present CSV snapshots, report **zero verified fully LLM-generated
JavaScript repositories and zero verified fully LLM-generated Python
repositories** under the explicit self-disclosure criterion. If career-ops is
used, place it in a separate *self-declared AI-assisted development* stratum.

Absence of a README declaration is not proof that no AI tool was used. It means
only that these repositories cannot be labelled LLM-generated using a
reproducible public self-disclosure rule.
