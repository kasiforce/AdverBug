# LLM-generated Java candidate audit

Audit date: 2026-10-29 (Asia/Shanghai).

## Measurement protocol

Each repository was shallow-cloned and fixed to the SHA recorded in
`candidates.csv`. Production Java files were parsed with
`extract_functions/java_extra.py` using Tree-sitter and Lizard. The exact
selection predicate was:

```text
method NLOC >= 100
AND cyclomatic complexity >= 10
AND syntactic call out-degree >= 5
```

The corresponding command-line parameters were `--min-loc 100
--min-complexity 10 --min-outgoing-degree 5`.

The call out-degree is a syntax-level count of distinct call expressions in a
method body. It includes object creation expressions and does not perform Java
type resolution. It must therefore be reported as *syntactic call out-degree*,
not as the number of statically resolved callees.

Production NLOC is the number of non-empty lines in files under
`src/main/java`. It is a project-size descriptor and is not the same measure as
Lizard method NLOC used by the selection predicate.

## Decision

1. **Use ResForge first.** It has explicit model-level provenance, a permissive
   license, five qualifying methods, and a reproducible green baseline: 428
   tests passed under Maven with JDK 21.
2. **Use NetbeansPluginClaudeCodeGui only in a separate GUI/component stratum.**
   It has five qualifying methods, but its Swing tests require a virtual display.
   A plain headless Maven run discovered 1,161 tests and produced 73
   `HeadlessException` errors. Its own CI uses `xvfb-run mvn package`. In
   addition, the README says its MCP integration is based on an earlier project;
   copied/adapted files should not be described as purely LLM-originated without
   a file-level provenance audit.
3. **Exclude content-dedup from the present function benchmark.** It has zero
   methods satisfying the predicate. Its two test classes are integration tests
   (`*IT`) coupled to Alfresco/Testcontainers, so it belongs to a system or
   integration-test benchmark if used at all.
4. **Exclude mini-agi-planner-hybrid.** Despite its project size and 1,410
   parsed methods, none satisfies all three thresholds. `mvn test` reports
   `No tests to run`, and the README's generic “created by LLMs” statement is
   weaker provenance evidence than the other candidates.

## Interpretation warning

These repositories were found through author self-disclosure. The audit verifies
that the disclosure exists; it does not independently prove that every source
line was generated by the named model. A paper should call these
*self-declared LLM-generated repositories* and record the disclosure URL, fixed
SHA, license, and any known reused upstream code.

The original `github_repos_java_projects_sorted.csv` was intentionally left
unchanged. Promote only accepted rows after defining whether the benchmark has
separate function, GUI/component, and integration strata.
